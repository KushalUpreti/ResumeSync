SECTION STRUCTURE
- The final rendered resume should map cleanly to these standard sections: contact, summary, skills, experience, education, projects, certifications.

- Do not add fields that are not present in the schema.

CONTACT INFORMATION
- Preserve full name, email, phone, and links exactly unless source notes explicitly provide corrections.
- Do not add photo, date of birth, nationality, marital status, street address, or other personal details.
- Do not invent city, state, location, LinkedIn, GitHub, or portfolio links. Include links only when present in the source data or source notes.

PROFESSIONAL SUMMARY
- Write a sharp, target-role summary in 2-4 sentences.
- Lead with a role label that matches the target role when supported by the source resume.
- Mention years of experience only if the source clearly supports it.
- Weave in 4-6 high-value keywords from the job description naturally when they are honest.
- Include one quantified achievement or clearly marked metric placeholder when useful and supported by the surrounding source material.
- Avoid fluffy adjectives such as "passionate," "dynamic," "results-driven," "hardworking," and "team player."
- Never make the summary a bulleted list.

SKILLS SECTION
- Target 15-20 total skill items grouped into 3-4 relevant categories when the source supports enough skills.
- Prefer these category labels when relevant: "Languages", "Frameworks & Libraries", "Cloud & DevOps", "Tools & Platforms", "Databases", "Methodologies".
- Use exact terminology from the job description where honest and supported.
- Prioritize skills that appear in both the job description and the candidate's source resume.
- Make sure the strongest 8-10 target skills also appear naturally in experience or project bullets when truthfully applicable.
- Do not include skill bars, proficiency ratings, icons, or visual indicators.
- Avoid soft skills as standalone skill items unless they already exist in the source. Demonstrate soft skills in bullets instead.

EXPERIENCE SECTION
- Preserve every role present in the source resume. Do not add roles not in the source.
- Keep roles reverse-chronological, most recent first.
- Preserve all start and end dates exactly as they appear in the source JSON. Never invent, estimate, reformat, or remove dates.
- Rewrite and reorder bullets to put the most job-relevant and highest-impact bullets first.
- For each role, write bullets using action, scope or process, and result.
- Start bullets with strong, varied action verbs. Avoid "responsible for," "assisted with," "helped," "worked on," and passive phrasing.
- Include named technologies in bullets where truthfully applicable, especially technologies present in the job description.
- Current or most recent role: 4-5 bullets when source material supports it.
- Recent prior roles: 3-4 bullets when source material supports it.
- Older roles: 2-3 bullets when source material supports it.
- Maximum 5 bullets per role.
- If a source bullet lacks a metric but would benefit from one, add a conservative review marker inline, such as "[METRIC: e.g., 15% reduction in processing time]", instead of inventing a factual number.
- Surface collaboration, communication, and leadership as demonstrated outcomes inside bullets rather than abstract claims.

EDUCATION
- Include degree, institution, field of study, GPA, dates, and description only when present in the source data.
- Include GPA only if it is present and 3.5+ on a 4.0 scale.
- Include honors or relevant coursework only if present in the source data.
- Preserve all dates exactly and sort most recent first.

PROJECTS
- Include projects only if present in the source data.
- Prioritize projects that best support the target role.
- Do not fabricate projects.
- Use 2-3 bullets per project when source material supports it.
- Name specific technologies used when present, especially technologies from the job description.
- Sort most recent first.

CERTIFICATIONS
- Include certifications only if present in the source data.
- Include certification name, issuer, date obtained, and URL only if present.
- Do not invent required certifications from the job description.
- Sort most recent first.

ATS-SAFE CONTENT RULES
- The final rendered document should avoid tables, text boxes, graphics, icons, skill bars, images, and content in headers or footers.
- Do not use creative section naming inside content that could confuse resume parsers.
- Spell out important abbreviations once when it fits naturally and does not bloat the content.

CONTENT GUARDRAILS
